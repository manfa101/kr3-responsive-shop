## Адаптивные решения

**Подход Mobile First.** В `style.css` описана мобильная версия: всё в одну колонку, крупные области нажатия. В `responsive.css` только медиазапросы `min-width`, которые расширяют раскладку.

| Точка | Что меняется |
|---|---|
| базовые стили (до 480px) | одна колонка, меню-гамбургер, фильтры свёрнуты, таблицы сравнения в виде карточек |
| `min-width: 480px` | кнопки в строку, преимущества по 2, подвал в 2 колонки |
| `min-width: 600px` | карточки товаров в 2 колонки, поля формы по 2 в строке |
| `min-width: 768px` | hero в 2 колонки, страница товара в 2 колонки, таблицы — обычный табличный вид, отзывы в 3 колонки |
| `min-width: 1024px` | горизонтальное меню, каталог с боковым sticky-фильтром, преимущества по 4, подвал в 4 колонки |
| `min-width: 1280px` | каталог в 3 колонки |
| `min-width: 1440px` | увеличенный базовый размер шрифта, шире боковой фильтр |

Что адаптировано:

- **Навигация.** На телефоне и планшете — кнопка-гамбургер. Она меняет `aria-expanded`, иконка превращается в крестик, меню закрывается по `Esc`. С 1024px меню горизонтальное.
- **Hero-блок.** На телефоне одна колонка и кнопки во всю ширину. Через `<picture>` показывается другое изображение (art direction): на телефоне крупная монстера, с 768px — композиция из трёх растений.
- **Сетка карточек.** CSS Grid: 1 → 2 → 3 колонки.
- **Каталог.**
  - Категории на телефоне — лента, которая прокручивается вбок внутри себя, а не вся страница.
  - Боковой фильтр на мобильном свёрнут под кнопку «Показать фильтры».
  - На десктопе фильтр всегда открыт и прилипает (`position: sticky`).
- **Страница товара.** Фото и описание сначала друг под другом, с 768px рядом. Блок советов с 1024px сбоку и прилипает.
- **Таблицы.** Обёрнуты в `.table-wrapper` с `overflow-x: auto`. Таблицы сравнения на телефоне превращаются в карточки: подписи ячеек берутся из `data-label`.
- **Формы.**
  - На телефоне одна колонка, с 600px — по два поля в строке.
  - Поля и кнопки высотой не меньше 44px.
  - Шрифт полей 16px, чтобы iPhone не увеличивал страницу при фокусе.
  - Кнопки на телефоне во всю ширину, с отступом между ними.
- **Модальное окно.** Не выше экрана (`max-height: 100dvh`), прокрутка внутри окна.
- **Подвал.** 1 → 2 → 4 колонки.

## Адаптивные изображения

- Для всех изображений: `img, video { max-width: 100%; height: auto; }`.
- **Карточки и фото товара:** `<picture>` с WebP и запасным JPG. В `srcset` три размера (480w, 640w, 960w), `sizes` зависит от числа колонок:
  ```html
  sizes="(min-width: 1024px) 300px, (min-width: 600px) 50vw, 100vw"
  ```
- **Hero:** `<picture>` с `media="(min-width: 768px)"` — на телефоне и десктопе разные картинки.
- У всех `<img>` заданы `width` и `height`, чтобы страница не прыгала при загрузке. Изображения ниже первого экрана — `loading="lazy"`.
- Проверка: DevTools → Network → Img. На ширине 360px грузится `monstera-480.webp`, на 1440px — версии крупнее.

## Доступность

- Ссылка «Перейти к содержимому» — первый элемент при нажатии Tab.
- Видимый фокус (`:focus-visible`) у ссылок, кнопок, полей, у обёртки таблицы.
- На каждой странице один `h1`, заголовки идут по порядку без пропусков уровней.
- Семантика: `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`, `address`, `dialog`, `details`.
- У всех полей есть `label` с совпадающими `for` и `id`, подсказки связаны через `aria-describedby`.
- У всех изображений осмысленный `alt`. Декоративные иконки скрыты через `aria-hidden="true"`.
- **Контраст:** все пары цветов проверены на порог WCAG AA (4.5:1):
  - серый текст на светлом фоне — 5.5:1;
  - белый текст на зелёных кнопках — 5.1:1;
  - активный пункт меню: исправлен с 4.0:1 на 6.0:1 (цвет `--color-primary-dark`).
- **Кнопки меню и фильтров:**
  - это настоящие `<button>`, а не ссылки;
  - есть `aria-expanded` и `aria-controls`;
  - закрываются по `Esc` с возвратом фокуса на кнопку.
- **Модальное окно** на `<dialog>`: фокус остаётся внутри окна, закрывается по `Esc`, крестиком или кликом по фону.
- **Работа без JavaScript:** меню и фильтры просто всегда раскрыты.
- **`prefers-reduced-motion`:** анимации отключаются, если пользователь включил это в системе.
- **Крупные области нажатия** на мобильном — не меньше 44px.

## Lighthouse

Проверены страницы `index.html`, `catalog.html` и `order.html` в категории Accessibility (Chrome DevTools → Lighthouse). Скриншоты отчётов лежат в папке `lighthouse/`.

## Проверенные ширины

360px, 430px, 768px, 1024px, 1440px — на всех страницах:

- нет горизонтального скролла всей страницы;
- шапка, меню, hero, сетка карточек, каталог с фильтром, страница товара, таблицы, формы, контакты, подвал и модальное окно отображаются корректно.

Как проверить: DevTools → Toggle device toolbar (Ctrl+Shift+M) → задать ширину вручную.

## Самостоятельные доработки

1. **Мобильное меню-гамбургер:** анимированная иконка, `aria-expanded`, закрытие по `Esc`, сброс при переходе на десктоп. Без JS меню остаётся раскрытым.
2. **Каталог:**
   - сворачиваемый фильтр на мобильном;
   - прокручиваемая лента категорий;
   - сетка карточек 1/2/3 колонки;
   - sticky-фильтр на десктопе.
3. **Таблицы сравнения:** на телефоне превращаются в карточки через `data-label`, на планшете и десктопе — обычные таблицы.
4. **Несколько вариантов адаптивных изображений:**
   - WebP + JPG;
   - `srcset` и `sizes`;
   - разные изображения в hero через `<picture>`;
   - прозрачный PNG/WebP в hero.
5. **Доступность:**
   - skip-link;
   - видимый фокус;
   - доступное модальное окно;
   - `prefers-reduced-motion`;
   - крупные области нажатия;
   - работа без JS.
6. **Подробный README** с таблицей контрольных точек.
7. **Публикация через GitHub Pages.**
